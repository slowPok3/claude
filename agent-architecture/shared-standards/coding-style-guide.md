# 📜 Shared Standard: Coding Style & Practices

## 1. BLUF (Bottom Line Up Front)
All code generated by the Architect Ecosystem must be **secure by design, highly readable, modular, and optimized for an IL5 DoW environment**. Code is written for human maintainability first, and machine execution second.

---

## 2. Universal Security & IL5 Mandates

Regardless of the language being used, all Domain Architects must strictly adhere to the following security protocols:

| Rule | Description |
|---|---|
| **Zero Trust** | Assume the network is hostile. All inter-service communications must be authenticated and encrypted. |
| **No Hardcoded Secrets** | Credentials, API keys, and tokens MUST NEVER be written in plain text. Use environment variables, Azure Key Vault, AWS Secrets Manager, or GitLab CI/CD masked variables. |
| **No PII/PHI** | Never generate, log, or process real Personally Identifiable Information or Protected Health Information. Use synthetic data for examples and testing. |
| **Principle of Least Privilege** | Scripts and applications must only request the exact permissions required to perform their specific function. |

---

## 3. Universal Error Handling & Logging

Code that fails silently is unacceptable in a mission-critical environment.

*   **Robust Exception Handling:** All executable logic must be wrapped in standard error-handling blocks (e.g., `try/catch` in PowerShell/Java, `try/except` in Python).
*   **Actionable Logging:** Catch blocks must output logs that specify *what* failed, *why* it failed (the exception message), and the *context* (e.g., the variable state at the time of failure).
*   **Graceful Exit:** If a critical component fails, the script must exit gracefully with a non-zero exit code to alert the GitLab CI/CD pipeline.

---

## 4. Language-Specific Standards

### 🛡️ PowerShell Architect Standards
*   **Advanced Functions:** All scripts must be structured as advanced functions using `[CmdletBinding()]` and `param()` blocks.
*   **Modern Modules:** Use modern SDKs (e.g., Microsoft Graph PowerShell) instead of deprecated modules (e.g., AzureAD, MSOnline).
*   **Verb-Noun Convention:** Strictly adhere to standard PowerShell Approved Verbs (e.g., `Get-`, `Set-`, `Invoke-`).
*   **Documentation:** Every script must include comment-based help (`.SYNOPSIS`, `.DESCRIPTION`, `.EXAMPLE`).

### 🐍 Python Architect Standards
*   **PEP 8 Compliance:** Code must adhere strictly to PEP 8 style guidelines.
*   **Type Hinting:** Use standard type hints (e.g., `def process_data(data: list) -> dict:`) for all function signatures to improve readability and catch errors early.
*   **Virtual Environments:** Assume all code runs in isolated environments (e.g., `venv` or Docker containers) with a defined `requirements.txt`.
*   **Modular Design:** Break complex logic down into small, testable classes or functions.

### ☕ Java Architect Standards
*   **Modern Java Features:** Utilize features from the current enterprise standard version (e.g., Records, Streams, Switch expressions) where appropriate.
*   **Framework Alignment:** Default to Spring Boot for enterprise middleware and microservices unless otherwise specified.
*   **Strong Typing & Encapsulation:** Enforce strict access modifiers (`private`, `protected`). Avoid raw types; always use generics.
*   **Build Tools:** Assume Maven or Gradle for dependency management. 

### 🦊 GitLab CI/CD Architect Standards
*   **Stage Definition:** Pipelines must explicitly define stages: `lint`, `test`, `build`, `security_scan`, and `deploy`.
*   **Image Optimization:** Use specific, hardened, and minimal container images for runners (e.g., `python:3.11-slim` or Alpine-based images).
*   **Artifact Management:** Explicitly define artifacts and their expiration policies to prevent storage bloat.
*   **Security Scanning:** Incorporate SAST (Static Application Security Testing) and dependency scanning jobs in all pipelines.
